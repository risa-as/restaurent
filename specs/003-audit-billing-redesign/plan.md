# Implementation Plan: System Audit, Billing Integration & Complete Visual Redesign

**Branch**: `003-audit-billing-redesign` | **Date**: 2026-03-15 | **Spec**: [spec.md](./spec.md)

---

## Summary

Complete production-readiness sprint for the restaurant SaaS platform covering three pillars:
1. **Security & Integrity**: Fix tenant isolation holes (optional tenantId pattern), add tenantId to financial models (Bill, DailyClose, Expense, Offer), centralize branch filtering, verify order financial accuracy
2. **Billing System**: Extend ManualPayment model with invoice fields, build `/dashboard/billing` redesign and `/superadmin/billing` dashboard, implement approve/reject workflow
3. **Visual Redesign**: Build shared design components (StatCard, EmptyState, DataTable, StatusBadge, ConnectionDot, PageHeader) and apply consistently across all pages

---

## Technical Context

**Language/Version**: TypeScript 5 / Next.js 14 App Router
**Primary Dependencies**: Prisma 5 (PostgreSQL/Neon), NextAuth v5, Pusher, shadcn/ui, Tailwind CSS 3, Lucide React, Recharts, date-fns
**Storage**: PostgreSQL (Neon serverless) — shared DB, tenant isolation via `tenantId` column
**Testing**: TypeScript compiler + manual integration testing (no automated test suite)
**Target Platform**: Web (desktop + tablet) — Arabic RTL, Iraqi market
**Project Type**: Multi-tenant SaaS web application
**Performance Goals**: All operational pages < 2s load, real-time events < 3s delivery
**Constraints**: No breaking changes to existing sessions/auth. Migrations must be backwards-compatible (nullable columns). No new npm packages unless essential.
**Scale/Scope**: ~50 screens across restaurant + superadmin. 4 Prisma schema migrations.

## Complexity Tracking

| Item | Why Needed | Simpler Alternative Rejected Because |
|------|------------|--------------------------------------|
| `getBranchFilter` utility | 5 action files duplicate branch logic | Inline duplication causes inconsistent behavior |
| Recalculate bill at settlement | Order total may diverge from items at settlement | Trusting `order.totalAmount` misses post-creation offer changes |
| PlatformSettings singleton upsert | Settings must always exist | Creating on first read is simpler than manual seeding |
