# Implementation Plan: Restaurant SaaS Comprehensive Upgrade

**Branch**: `004-saas-restaurant-upgrade` | **Date**: 2026-03-23 | **Spec**: [spec.md](./spec.md)

## Summary

Close all functional and security gaps identified in a comparative analysis of the system against global restaurant management platforms (Toast, Foodics, Square, Oracle MICROS), optimised for the Iraqi market. The upgrade covers 16 feature areas across 3 priority phases plus a security hardening track. All changes are additive — no existing functionality is broken.

---

## Technical Context

**Language/Version**: TypeScript 5.x
**Primary Dependencies**: Next.js 14.2 (App Router), Prisma 5, NextAuth v5, shadcn/ui (Radix UI), Tailwind CSS, Pusher, Resend, next-pwa
**New Dependencies**: `otplib` (TOTP 2FA), `qrcode` (2FA setup QR), `next-intl` (i18n), `idb` (IndexedDB offline queue)
**Storage**: PostgreSQL 15+ with Row-Level Security
**Testing**: `npm run lint` (ESLint), manual testing per quickstart.md
**Target Platform**: Web (desktop + mobile), PWA
**Performance Goals**: QR order acknowledged <3s; tracking page <3s load; consolidated report <5s for 10 branches / 90 days
**Constraints**: Offline-capable (cashier + captain); Iraq timezone (UTC+3); IQD currency; RTL Arabic + Kurdish
**Scale/Scope**: Multi-tenant SaaS; up to 10 branches per tenant; 11 user roles; ~16 new feature areas

**Complexity Tracking**:

| Addition | Why Needed | Simpler Alternative Rejected Because |
|----------|------------|--------------------------------------|
| `InventoryBatch` model | FIFO expiry tracking requires per-batch records | Adding `expiryDate` to `RawMaterial` doesn't support multiple batches of the same material |
| `CashierShift` model | Per-shift cash accountability and multi-shift per day | `DailyClose` is one-per-day and doesn't support multiple cashiers |
| `VoidRequest` workflow | Supervisor approval for financial voids | Direct void without approval creates segregation-of-duties gap |
| `next-intl` i18n library | Kurdish + Arabic + English with App Router server components | `react-i18next` doesn't support RSC; manual translation map is unmaintainable |

## Implementation Phases

---

### Phase 1 — Critical (ship first)

#### 1.1 Database Schema Migration
Update `prisma/schema.prisma` with all models from `data-model.md`. Run migration. All FK additions are nullable.

#### 1.2 Modifier Groups & Variants
- Server actions: `getModifierGroups`, `createModifierGroup`, `updateModifierGroup`, `assignModifierGroupToItem`
- `OrderItemModifier` records snapshot prices at order time
- Inventory deduction includes modifier option raw-material adjustments
- Kitchen ticket + receipt display modifier selections
- Admin UI: modifier manager tab in menu item edit sheet
- Order forms (captain, cashier, QR): modifier picker modal before adding to cart

#### 1.3 QR Self-Ordering
- Route group `(customer)/[slug]/order` excluded from NextAuth middleware
- `qr_session` cookie (UUID v4, HttpOnly, 24h) for session identity
- API routes: `/api/qr/{order, order-status, bill-request}`
- Pusher subscription on `table-{tableId}` for real-time status
- QR code URL updated in table management page

#### 1.4 Password Reset Flow
- `/forgot-password` + `/reset-password` pages
- `/api/auth/{forgot-password, reset-password}` routes
- SHA-256 hashed token, 30-min expiry, single-use
- React Email templates: reset link + confirmation
- Always returns success (anti-enumeration)

#### 1.5 Offline Mode (PWA)
- `next-pwa` cache strategies: CacheFirst for assets, NetworkFirst for API with 5s timeout
- `offline-queue.ts`: IndexedDB `offlineOrders` store with `enqueueOrder` / `drainQueue`
- Online/offline banner in cashier + captain layouts
- `window.addEventListener('online', drainQueue)` in root layout
- Offline orders tagged with `[OFFLINE SYNC]` note

#### 1.6 Security Hardening (Core)
- Login attempt tracking (`LoginAttempt` model): 10 failures in 15 min → 15-min lockout
- Session maxAge: 8 hours
- CSP headers in `next.config.js` with per-request nonce
- Explicit CORS allowlist in middleware for `/api/*`
- `withAudit()` wrapper applied to all financial mutations

---

### Phase 2 — Important

#### 2.1 Split Bill
- `BillSplit` + `BillSplitItem` models
- Equal split or item-assignment modes
- Each portion settled independently; order closes when all portions paid

#### 2.2 Shift Management
- `CashierShift` model; shift required before cashier can process payments
- `openShift`, `closeShift`, `getCurrentShift`, `getShiftHistory` actions
- Bills linked to shift via `shiftId` FK
- Shift closing report: expected cash vs physical count, variance

#### 2.3 Purchase Orders & Stock Expiry
- `PurchaseOrder` → `PurchaseOrderItem` → `InventoryBatch` models
- FIFO consumption utility in `order-completion.ts`
- `/api/cron/expiry-check`: daily Pusher alerts at 7-day and 3-day windows
- PO management UI in `/inventory/purchase-orders`

#### 2.4 Customer Delivery Tracking
- `DeliveryTrackingToken` generated on driver assignment
- SMS notification with tracking URL (Twilio, optional)
- `/track/[token]` public page: Leaflet map + Pusher live updates + order stages + Haversine ETA

#### 2.5 Two-Factor Authentication (TOTP)
- NextAuth partial session flow: password OK → `requires2FA` flag → `/auth/2fa`
- `otplib` for secret generation + verification; `qrcode` for setup QR
- AES-256-GCM encrypted secret in `User.twoFactorSecret`
- 8 bcrypt-hashed backup codes
- SUPER_ADMIN: 2FA forced on first login

#### 2.6 Talabat Integration
- `/api/webhooks/talabat`: HMAC-SHA256 signature verification + idempotency check
- Inbound webhook → Order + OrderItems creation
- Outbound: status hook in `updateOrderStatus` action
- `/api/talabat/sync-menu`: push menu to Talabat API
- `TalabatConfig` per-tenant credential model

---

### Phase 3 — Competitive Differentiation

#### 3.1 Kitchen Stations (KDS)
- `KitchenStation` + `MenuItemStation` models
- `/kitchen/station/[stationId]` per-station board filtered by assigned items
- Auto-advance order to READY when all station items completed
- Prep time alerts (red highlight when `now - prepStartedAt > prepTimeMins`)

#### 3.2 Digital Menu Boards
- `/display/[slug]` — public, dark TV layout, Pusher live updates
- Items disappear within 10s of being marked unavailable
- Night menu scheduling via time-range config on Tenant

#### 3.3 Kurdish Language (i18n)
- `next-intl` with `messages/{ar,ku,en}.json`
- `User.language` field; `NEXT_LOCALE` cookie for unauthenticated pages
- `MenuItem.nameAr/nameKu/nameEn` + `Category.nameAr/nameKu/nameEn` fields
- Full RTL support for Kurdish (same as Arabic)

#### 3.4 Customer Feedback / NPS
- Feedback prompt on QR order tracker after COMPLETED status
- `POST /api/feedback` rate-limited by orderId + session
- Google Reviews redirect for rating ≥ 4 if `Tenant.googlePlaceId` set
- `/dashboard/feedback`: average, distribution, trend, recent comments

#### 3.5 Seasonal / Ramadan Menus
- `SeasonalMenu` + `SeasonalMenuCategory` + `SeasonalHours` models
- `/api/cron/seasonal-menus`: daily date-based auto-activation
- `getCategories()` filters by active seasonal menu
- Operating hours override during active seasonal period

#### 3.6 Consolidated Branch Reports
- `getConsolidatedReport(tenantId, from, to)` — single grouped Prisma query
- `/dashboard/reports/consolidated` page for ADMIN/MANAGER/ACCOUNTANT
- Excel export with per-branch sheets + totals row

---

### Phase 4 — Security Hardening (Remaining)

#### 4.1 PostgreSQL Row-Level Security
- `app_user` Postgres role; `SET LOCAL app.tenant_id` Prisma extension
- RLS policies on all 16 tenant-scoped tables
- Script: `src/lib/rls/setup.sql`

#### 4.2 VoidRequest Supervisor Approval
- Cashier void → creates `VoidRequest` (PENDING) → Pusher to manager
- Manager approves → order cancelled + AuditLog with before/after values
- Manager dashboard badge for pending void requests

#### 4.3 Audit Log Completeness
- `withAudit()` utility captures entity state before + after every financial mutation
- Applied to: expense CRUD, markOrderAsPaid, dailyClose, openShift, closeShift, voidApproval

## Risk Register

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| Talabat API differs from contract | Medium | High | Adapter pattern; stub for testing without live Talabat account |
| RLS breaks existing queries | Low | High | Test in staging; off-by-default in dev |
| Offline sync duplicates | Low | Medium | Client UUID idempotency key per queued order |
| CSP breaks Pusher/Stripe | Medium | Medium | Test in staging with all integrations; nonce-based policy |
| next-intl routing breaks existing URLs | Low | High | Keep existing routes; locale is optional path segment |
| TOTP secret storage compromise | Low | High | AES-256-GCM with AUTH_SECRET; rotate = invalidates all 2FA |
