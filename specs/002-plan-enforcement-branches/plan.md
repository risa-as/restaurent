# Implementation Plan: Plan Enforcement, Multi-Branch & Cashier Auto-Sync

**Branch**: `002-plan-enforcement-branches` | **Date**: 2026-03-15 | **Spec**: [spec.md](./spec.md)

---

## Summary

Enforce SaaS plan limits server-side (TRIAL/BASIC/PRO/ENTERPRISE), add multi-branch support as an ENTERPRISE-only feature (new `Branch` model + branchId FKs), and make the cashier page automatically show only the relevant tab based on the restaurant's serviceMode. All three features are interconnected: plan enforcement gates multi-branch access, and the cashier auto-sync uses the same branch/serviceMode lookup.

---

## Technical Context

**Language/Version**: TypeScript 5.x / Next.js 14.2 (App Router)
**Primary Dependencies**: Prisma 5 (PostgreSQL), NextAuth v5, shadcn/ui (Radix), Tailwind CSS, Lucide React
**Storage**: PostgreSQL via Prisma ORM — `db push` workflow (no migration files)
**Testing**: Manual + type-checking (`tsc --noEmit`)
**Target Platform**: Web (server-side rendered, multi-tenant SaaS)
**Project Type**: Web application (multi-tenant restaurant management)
**Performance Goals**: Plan checks add <5ms overhead per request (single DB row read, cached per request)
**Constraints**: All FKs nullable (no downtime for existing data); cookie-based branch selection persists across page refreshes
**Scale/Scope**: ~10–100 active tenants; up to 20 branches per ENTERPRISE tenant
